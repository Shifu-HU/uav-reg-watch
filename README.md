# UAV Reg Watch — Drone Regulation Radar

Watches the CAAC (Civil Aviation Administration of China) website daily for new drone
regulations, filters them by your location and the weight class of your registered
drones, and summarizes everything with a small local model. Windows desktop + Android,
all data stays on the device.

## What it does

| Capability | Notes |
|---|---|
| First launch | Full historical crawl to build a local baseline database |
| Daily schedule | 07:30 by default; if the machine was off, it catches up on first open |
| Sources | CAAC website (primary) + Bing + SearXNG (optional) + local agencies |
| Analysis | A local model produces summary / category / importance / effective date; falls back to rule-based parsing without one |
| Three-tier severity | Major / Important / Normal, colour-coded in the list |
| Geo filtering | Keeps national + local + same-province rules; the rest land in a "Filtered" page |
| Device filtering | Register a model (brand → series → model, weight filled in automatically) and only matching rules are pushed |
| Weather & endurance | Fetches local weather and estimates real usable flight time from wind, with gust warnings |
| Morning brief | A daily HTML brief, read in the embedded browser |
| Appearance | Dark / light × 8 colour schemes; level colours derive from the active scheme |

## Download & Install

Grab the latest release (v2.5) from the [Releases](https://github.com/Shifu-HU/uav-reg-watch/releases/latest) page.

**Desktop**: download the desktop archive, unzip, and double-click `UAVRegWatchMine.exe`.
No installer — `config.yaml` and `data/` live next to the executable, and deleting the
folder uninstalls everything. Windows 10/11 x64.

**Android**: copy the APK (~489 MB) to your phone and tap it to install; allow the
"unknown sources" prompt when it appears. Requires Android 8.0+, arm64, and 1 GB+ of
free storage.

> The APK bundles a ~470 MB local model. On first launch it is extracted into the app
> directory — the screen may sit still for tens of seconds to a couple of minutes.
> That is normal; later launches are fast.

> The one-line summary in the app is generated by a small local model and is meant for
> quick scanning only — it may differ from the original text. Open each item's source
> link and treat the official announcement as authoritative, especially for no-fly
> zones, penalties and registration.

## First-run setup

1. **Location**: set your city and province in Settings. Changes save automatically and
   immediately trigger a full re-search; rapid changes are debounced into one pass.
2. **My devices**: register a drone model and its weight is filled in automatically, so
   only rules matching that weight class are pushed. Models that cross a class boundary
   with a bigger battery (e.g. Mini 5 Pro, 249–310 g) are classified by the maximum and
   displayed as a span.
3. **Local model** (optional): install [Ollama](https://ollama.com) and pull `qwen3.5:0.8b`.
   The app works without any model — summaries and categories just degrade to rule-based
   parsing.

## Daily use

The sidebar has five pages: **Feed** (daily rules), **Brief** (the day's HTML brief),
**Filtered** (rules dropped by the location/device filters, still viewable), **Starred**
and **Settings**.

Colour schemes and dark/light mode apply instantly in Settings; the morning brief
follows the same theme. The desktop and Android editions keep separate databases —
they crawl independently and do not sync.

## Configuration (config.yaml)

The desktop config file sits next to the executable; anything editable in the UI
(location, devices, appearance) is written back automatically:

```yaml
location:
  city: Shenzhen
  province: Guangdong
  keep_national: true      # keep nationwide rules

devices:
  - brand: DJI
    model: Mini 5 Pro
    grams: 310.0           # span maximum; classification uses the worst case
    level: Light

schedule:
  daily_time: "07:30"      # daily crawl time
  min_daily_items: 0       # 0 = no lower quota

llm:
  provider: ollama
  model: "qwen3.5:0.8b"

appearance:
  mode: dark               # dark / light
```

## Implementation notes

- **Scraping the CAAC site**: the site search must use POST — GET gets 302-redirected
  to an anti-bot shell page. The agency footer on CAAC pages must be stripped, or
  national rules get misclassified as Guangzhou local documents.
- **Geo decision order**: local city/province → other cities in the same province →
  regional CAAC bureau (Shenzhen belongs to the Central-South bureau) → national marker
  words → everything else is dropped. Provincial policy applies province-wide, so
  same-province items are kept.
- **Weight classes**: four tiers per CAAC — Micro < 0.25 kg, Light 0.25–4 kg,
  Small 4–15 kg, Medium 15–116 kg. Boundaries are inclusive (exactly 250 g is Light).
- **One palette for both ends**: `theme.build_tokens()` is the single source of truth —
  the desktop turns it into QSS, Android converts it to CSS variables over
  `/api/theme.css`, so colours never drift between the two.

## Running from source

The repository contains the core engine (`src/uavwatch`) and the Android project
(`src/android`).

```bash
pip install -r requirements.txt

python -m uavwatch.cli bootstrap    # first full baseline crawl
python -m uavwatch.cli run          # one incremental pass
python -m uavwatch.cli status       # status summary
python -m uavwatch.cli brief        # build today's brief
python -m uavwatch.tui              # live progress in the terminal
```

Android side: `src/android/` holds the Java shell, the FastAPI server
(`phone_server.py`) and a PySide6 stub (Android has no real Qt; only colour parsing is
kept). The APK is built with Chaquopy (embedded CPython) and runs the model on-device
via llama.cpp (`libllamaserver.so`).

## FAQ

| Problem | Notes |
|---|---|
| First open is slow / looks frozen | The desktop is building the baseline, the phone is extracting the model — let it finish |
| Missed the 07:30 run | It catches up automatically on the first open of the day |
| No Ollama installed | Works fine; summaries/categories degrade to rule-based parsing |
| Do phone and PC sync? | No — the two editions crawl independently |
| A local rule is missing | Check the Filtered page first; then verify the location setting and the registered device's weight class |
